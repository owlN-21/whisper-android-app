# Audio Summary Main Backend

## О проекте

`Audio Summary Main Backend` - это основной сервер приложения для обработки аудиофайлов.

Он выступает промежуточным слоем между Android-приложением и `processing-service`.

Основная задача сервера - принять запрос от Android, сохранить информацию о пользователе и задаче обработки, передать аудиофайл в `processing-service`, а затем сохранить и отдать результат обратно клиенту.

Общий pipeline системы выглядит так:

```text
Client → Main Backend → Processing Service → Main Backend → Client
```

Сам `main backend` не выполняет распознавание речи и не генерирует summary самостоятельно. Эти задачи выполняет отдельный `processing-service`. Подробное описание его логики находится в README `processing-service`, где описан pipeline `аудио → транскрипция → структурированный конспект`.

---

## Роль main backend в системе

Main backend отвечает за:

* прием запросов от Android-приложения;
* создание пользователей;
* загрузку аудиофайлов;
* сохранение аудиофайлов в локальное хранилище;
* создание задач обработки;
* хранение статусов задач;
* взаимодействие с `processing-service`;
* сохранение transcript и summary в базе данных;
* предоставление результатов Android-клиенту через REST API.

## Основные сущности

В проекте используются следующие основные сущности:

### User

Пользователь приложения.

Хранит базовую информацию о пользователе, например email.

### ProcessingTask

Задача обработки аудиофайла.

Создается после загрузки аудио пользователем.
Содержит информацию о файле, пользователе, статусе обработки и возможной ошибке.

### Transcript

Распознанный текст аудиофайла.

Создается после того, как `processing-service` завершил этап транскрибации.

### Summary

Итоговый структурированный конспект.

Создается после завершения этапа суммаризации текста.

## Статусы задачи

Задача обработки может находиться в одном из следующих статусов:


* `TRANSCRIBING` - аудио отправлено на распознавание;
* `SUMMARIZING`  - транскрипция получена, идет генерация summary;
* `COMPLETED` - обработка завершена, transcript и summary доступны;
* `FAILED` - произошла ошибка, подробности можно посмотреть в `errorMessage`.


## Как работает обработка аудио

После загрузки аудиофайла backend выполняет следующий сценарий:

1. Клиент отправляет аудиофайл на main backend.
2. Backend проверяет, что пользователь существует.
3. Backend сохраняет аудиофайл в локальное хранилище.
4. Backend создает задачу обработки в базе данных.
5. Backend отправляет аудио в processing-service на транскрибацию.
6. Задача получает статус TRANSCRIBING.
7. Клиент периодически запрашивает состояние задачи через endpoint получения задачи.
8. Backend проверяет результат транскрибации в processing-service.
9. Когда транскрипция готова, backend сохраняет transcript в базу данных.
10. Backend отправляет полученный transcript в processing-service на суммаризацию.
11. Когда summary готово, backend сохраняет его в базу данных.
12. Задача получает статус COMPLETED.
13. Клиент может получить transcript и summary через отдельные endpoint-ы.

На текущем этапе клиентом может быть Postman, curl или другое средство ручного тестирования API.

Подробный сценарий запросов к backend описан в инструкции `StartingServer.md`

## Запуск проекта

Подробные команды запуска вынесены в отдельную инструкцию `Instruction.md`.

### Локальный запуск

```shell
mvn clean package
mvn spring-boot:run
```

Проверка:

```text
GET http://localhost:8080/health
```

### Запуск через Docker Compose

```shell
mvn clean package
docker compose up --build
```

Проверка:

```text
GET http://localhost:8080/health
```

Если backend запускается вместе с `processing-service`, оба сервиса должны находиться в общей Docker network. Подробная настройка сети описана в `StartingServer.md`.
