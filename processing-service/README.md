# Processing Service

## О проекте

`Processing Service` — это сервис для обработки аудио, который преобразует речь в структурированный текст.

Основной сценарий работы состоит из двух последовательных этапов:

1. аудиофайл передается в ASR-модель;
2. полученная транскрипция передается в LLM, которая формирует структурированный конспект.

Таким образом, сервис реализует pipeline:

**аудио → транскрипция → структурированный конспект**

Помимо основного сценария, в проекте также сохранены результаты оценки ASR-моделей. В рамках исследования сравнивались модели `Whisper` и `T-one` по метрикам `WER` и `CER`. В данной документации акцент сделан именно на основном сервисе обработки аудио, а результаты оценки рассматриваются как готовые артефакты проекта.

---

## Что реализовано

В проекте реализован основной pipeline обработки аудио:

- чтение аудиофайла;
- распознавание речи с помощью ASR-модели;
- сохранение транскрипции в файл;
- передача текста в языковую модель;
- генерация структурированного конспекта;
- сохранение итогового результата.

Также в проекте сохранены результаты сравнительной оценки ASR-моделей, которые можно использовать для анализа качества распознавания речи.

---

## Нефункциональные особенности

Проект ориентирован на локальный запуск в контейнеризированной среде.

Основные особенности:

- запуск организован через Docker;
- языковая модель используется через `Ollama` в отдельном контейнере;
- `processing-service` взаимодействует с `Ollama` по внутренней сети Docker;
- данные `Ollama` сохраняются в отдельном volume;
- результаты работы сохраняются в файловую структуру проекта.

---

## Структура проекта

### `asr`

Пакет с логикой распознавания речи.

Здесь находятся базовые абстракции транскрибации, реализация ASR-модели, DTO результата распознавания и компоненты, связанные с обработкой аудио.

### `llm`

Пакет с логикой суммаризации текста.

Содержит DTO результата суммаризации, сервис работы с `Ollama` и компоненты для сохранения итогового структурированного конспекта.

### `data`

Папка с датасетом в формате `.parquet`, который использовался при оценке моделей распознавания речи.

### `models`

Папка для локальных файлов модели `T-one`.

### `artifacts`

Папка с артефактами, формируемыми в ходе работы проекта.

### `artifacts/metrics`

Папка с готовыми результатами оценки моделей.

Здесь находятся:
- предсказания моделей;
- отчеты по метрикам;
- графики сравнения.

### `start.py`

Основная точка входа для запуска основного сценария обработки аудио:
транскрибация речи и генерация структурированного конспекта.

---

## Основной сценарий работы

Основной сценарий запускается через `start.py`.

Во время выполнения:

1. берется аудиофайл `audio.mp3`;
2. речь распознается ASR-моделью;
3. транскрипция сохраняется в `output.txt`;
4. текст передается в LLM;
5. модель формирует структурированный конспект;
6. результат сохраняется в `summary.txt`.

На текущем этапе в основном сценарии используется модель `Whisper`, а для генерации конспекта применяется `Ollama` с моделью `Qwen2.5:7b`.

---

## Используемые модели

### Whisper

Используется как ASR-модель в основном сценарии обработки аудио.

Для распознавания речи применяется библиотека `faster-whisper`.

### T-one

Использовалась как альтернативная ASR-модель в исследовательской части проекта при сравнительной оценке качества распознавания речи.

### Qwen2.5:7b

Используется как языковая модель для генерации структурированного конспекта через `Ollama`.

---

## Результаты оценки моделей

В проекте уже присутствуют готовые результаты оценки ASR-моделей.

Сравнение выполнялось для моделей:

- `Whisper`
- `T-one`

Для оценки использовались метрики:

- `WER`
- `CER`

Итоговые артефакты сохранены в директории `artifacts/metrics`. Они включают текстовые предсказания моделей, отчеты по метрикам и графики сравнения.

---

## Назначение проекта

Проект предназначен для локальной обработки аудиозаписей и преобразования их в структурированный текст.

Он может использоваться как прототип backend-части системы, в которой аудио пользователя проходит два этапа обработки:

1. автоматическое распознавание речи;
2. автоматическое формирование краткого структурированного содержания.

Такой подход можно использовать как основу для дальнейшей интеграции с основным backend-сервисом и клиентским приложением.
